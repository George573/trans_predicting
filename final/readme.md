# Прогноз посадок на трамвайных маршрутах Москвы

Решение кейса «ИИ-прогноз загрузки трамвайных маршрутов» хакатона Московского транспорта:
модель почасового прогноза посадок на десяти трамвайных маршрутах и диспетчерский
веб-сервис вокруг неё. Этот файл - вводная точка: что решали, что получилось и где
читать подробности.

## Задача

**Посадка** - одна успешная валидация проездного документа в трамвае, любым способом
оплаты. Прогнозируется число посадок на маршруте за календарный час.

Исходные данные - сырые валидации за январь-октябрь 2025 года (304 дня) по маршрутам
`1, 5, 7, 11, 12, 17, 25, 26, 28, 50`. Прогноз нужен на ноябрь-декабрь 2025 года, данных за
который у участников нет: плотная сетка `маршрут x дата x час` из 10 x 61 x 24 = 14 640
значений, построенная целиком заранее, как продолжение временного ряда.

Метрика качества:

    WAPE       = sum|y - prediction| / sum(y)
    WAPE-score = max(0, 1 - WAPE)

Метрика глобальная: ошибки и объёмы суммируются по всей сетке сразу, поэтому крупный
маршрут весит в ней пропорционально своему объёму. Верхняя полоса оценки жюри начинается с
WAPE-score 0.88, базовый пример организаторов даёт около 0.48.

Две особенности данных определяют многое в решении:

- **маршрут 5** в истории не имеет ни одной успешной валидации, но обязан быть в прогнозе.
  По словам организаторов, нули по нему стоят около 0.0065 метрики, то есть потолок
  достижимого WAPE-score с нулями по маршруту 5 - 0.9935;
- **посадки нельзя привязать к остановке и направлению**: номер остановки в валидациях
  практически не обновляется в течение суток, а справочник координат покрывает пять
  маршрутов из десяти. Прогноз строится на уровне маршрута целиком, это согласовано с
  заказчиком.

## Результат

| Модель | Роль | WAPE-score на ноябре-декабре 2025 |
|---|---|---:|
| CNN по почасовой истории, календарю и событиям | основная модель решения | **0.88646** |
| Ансамбль CatBoost + MLP с калибровкой и постобработкой | резервная модель и база исследований | **0.88466** |

Обе модели превышают порог верхней полосы 0.88. Оценка получена платформой хакатона на
скрытом эталоне ноября-декабря, локально она не воспроизводима по определению.

![Путь к результату](docs/img/score_progress.svg)


**CNN** - основная модель. Она кодирует последние 14 суток истории маршрута свёрточной
сетью и по этому коду выдаёт 24 почасовых значения на любой из следующих 61 дня. Это
лучший результат решения, на 1.8 пункта выше ансамбля. Подробно -
[model-ai.md](docs/model-ai.md).

**Classical ML** - ансамбль градиентного бустинга и нейросети с эмбеддингами на
календарных признаках, без использования недавней истории. Он остаётся резервом и
инструментом для вопросов, на которые CNN по устройству не отвечает: прогноз на год вперёд
(у CNN горизонт ограничен 61 днём) и прогноз для новой линии без истории. Подробно -
[model-ml.md](docs/model-ml.md).

## Главные выводы работы

1. **Ошибка прогноза растёт не с горизонтом, а с разрывом сезонного уровня.** Календарная
   модель одинаково точна на 2 и на 9 месяцев вперёд, если целевой месяц похож по уровню
   спроса на обучающие. Прогноз на весь 2026 год оценён в WAPE-score 0.854 по часам, 0.888
   по суткам и 0.924 по месячным итогам. Главный неизмеримый риск - годовой тренд: 5% роста
   спроса стоят дороже, чем переход от двух месяцев к двенадцати.
   [research-horizon.md](docs/research-horizon.md)
2. **Новую линию в день открытия предсказать нельзя, через неделю - почти как обычную.**
   Суточная и недельная форма спроса переносится между маршрутами, а объём по географии не
   угадывается. Одна неделя собственных валидаций даёт WAPE-score 0.864, две - 0.892.
   Исследование ещё продолжается. [research-geo.md](docs/research-geo.md)
3. **Внешний источник полезен только при симметричном покрытии обучения и прогноза.**
   Признак изменений маршрутов улучшил бэктест на 0.81 пункта и ухудшил реальный прогноз на
   0.12 пункта, потому что данные о перекрытиях кончались вместе с обучающей выборкой. Фактическая
   погода прогнозных дней, наоборот, стоила на бэктесте и дала +0.198 пункта на цели.
   Календарь - самый сильный и полностью заранее известный фактор.
   [data.md](docs/data.md)
4. **Почасовой прогноз по календарю не может быть точнее примерно 0.12 WAPE в среднем за
   год.** Остаток - шум конкретного дня, которого в календаре нет. Суточные итоги точнее
   почасовых на 25-30%, месячные - на 50-60%.
5. **Кэш и предрасчёт не нужны.** Сервис считает модель на каждый запрос. На прод-хосте
   с 2 vCPU прогноз всей сети на 30 суток по часам занимает у CatBoost 13 мс, у CNN 52 мс,
   на 61 сутки по суткам - 24 и 102 мс. Смесь запросов диспетчера на Apple M4 - 2 544 RPS
   при p95 10.92 мс без ошибок. [perfomance.md](docs/perfomance.md)

Здесь и далее **пункт** - одна сотая WAPE-score, то есть 0.01.

## Сервис

Go-сервис в `service/` держит в памяти обе модели - CatBoost и CNN - и считает прогноз на
каждый запрос: маршрут или набор маршрутов, период, почасовая или посуточная детализация,
горизонт день, неделя, месяц или сезон. Модель выбирается полем `model` в запросе. К прогнозу
применяются сценарные условия из каталога с паспортами (дождь, температура, событие, задержка,
отмена, изменение маршрута), ответ несёт коридор, обычный уровень и аудит каждого условия.
Любую точку можно разобрать на шаги («как посчитано»), прогноз - выгрузить в CSV или XLSX.
При старте сервер сверяет обе модели с эталоном Python на всей сетке ноября-декабря и не
запускается при расхождении. Python в рантайме нет, поставка - один контейнер Docker Compose.

Сервис развёрнут на https://mttech.k1rles.ru. Там работает только API: интерфейса у нового
API пока нет, корень `/` отвечает 404. Прежний стенд со встроенным интерфейсом на трёх
коэффициентах сохранён на хосте как копия для отката.

| Что | Состояние |
|---|---|
| Go API по контракту `api/openapi.yaml`, обе модели | реализовано, развёрнуто |
| CNN с календарём и событиями, голова в Go | реализовано, версия 0.88499 |
| Условия, коридор, обычный уровень, разбор, CSV и XLSX | реализовано |
| Golden-сверка обеих моделей при старте | реализовано, на хосте прошла |
| Нагрузочный замер | на Apple M4; на прод-хосте не проводился |
| Интерфейс на новом API, карта линий | не сделан |
| CNN вне 2025-11-01 ... 2025-12-31 | нужен новый бандл |

Устройство, диаграммы и границы реализации - [system.md](docs/system.md), запуск, бандлы и
известные ограничения сервиса - `service/README.md`, контракт - `api/openapi.yaml`.

## Область применимости

- **Маршруты:** десять заданных, каждый целиком. Остановки, участки и направления не
  прогнозируются: в данных нет пригодной привязки.
- **Горизонт:** оперативный - до двух месяцев с заявленной точностью, это основная зона CNN;
  плановый - до года на уровне суток и месяцев, это зона календарной модели.
- **Внешние факторы:** учитываются глобально для города, без привязки к участку линии.
- **Не прогнозируются:** наполнение салона, число вагонов на линии, переток пассажиров между
  маршрутами и видами транспорта. Посадка - это валидация: пассажир на три остановки и
  пассажир на весь маршрут дают по одной.

Полный список ограничений и план развития - [roadmap.md](docs/roadmap.md).
