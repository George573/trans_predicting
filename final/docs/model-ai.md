# Флагманская CNN-модель

## Роль в решении

CNN — основная модель, предназначенная для продуктового контура. Она кодирует историю
маршрута свёрточной сетью один раз и затем выдаёт 24 почасовых значения для каждого
запрошенного дня. Classical ML остаётся резервным воспроизводимым контуром и используется
для исследований горизонта и переноса.

Сведения относятся к `origin/feature/cnn`, commit `244db07`. Эта ветка ещё не объединена
с `main`.

## Результат

Последняя версия CNN с календарём и известными заранее событиями получила
**WAPE-score `0.88499`**. Это немного выше classical ансамбля `0.88466`.

Результат относится к модели, а не к полностью интегрированному сервису: после добавления
новых входов изменились размеры энкодера и головы, а существующий Go-exporter всё ещё
рассчитан на предыдущую boarding-only версию.

## Входы

Для каждого контекста используются 14 дней, или 336 часов, истории. В текущей архитектурной
документации перечислены 13 каналов:

- нормированное число посадок;
- sin/cos часа, дня недели и дня месяца;
- праздник, выходной и сокращённый рабочий день;
- продлённая ночная работа транспорта;
- событие рядом с маршрутом;
- общегородское событие.

Для каждого будущего дня подаются:

- календарные признаки дня;
- те же три событийных флага, агрегированные максимумом за сутки;
- идентификатор маршрута;
- lead от 1 до 61 дня.

Признаки изменений маршрута и загрузки парковок исключены из CNN: их покрытие и переносимость
оказались недостаточно надёжными. Будущие валидации не используются.

## Архитектура

| Слой | Выход |
|---|---|
| 13 входных каналов × 336 часов | `13 × 336` |
| Conv1d `13→40`, kernel 50, GELU, pooling, dropout | `40 × 168` |
| Conv1d `40→40`, kernel 50, GELU, pooling, dropout | `40 × 84` |
| Conv1d `40→20`, kernel 50, GELU, pooling, dropout | `20 × 42` |
| Flatten | `840` |
| + route embedding 8, target calendar/events 10, lead 1 | `859` |
| Linear `859→320→320→24` | 24 часа |
| Softplus × scale | неотрицательные посадки |

Свёртки сохраняют длину перед pooling. Один исторический контекст кодируется один раз,
после чего общая голова применяется ко всем будущим дням. Это снижает цену длинного запроса.

## Обучение

- функция потерь: MAE в исходных единицах;
- оптимизатор: AdamW;
- early stopping: по validation WAPE;
- gradient clipping: `1.0`;
- seed: `67`;
- максимальный горизонт: 61 день;
- предсказания не подаются обратно в историю;
- маршрут 5 обрабатывается внешним fallback.

Валидационная история заканчивается 1 сентября, final refit — 1 ноября. Выбор чекпойнта и
финальное переобучение разделены, чтобы не использовать прогнозный период для отбора модели.

## Календарь и события

Производственный календарь хранится в XML и различает:

- официальный праздник или перенесённый выходной;
- обычный выходной с учётом рабочих суббот;
- сокращённый рабочий день.

Для нового года требуется отдельный проверенный XML. Отсутствующий или некорректный календарь
вызывает ошибку, а не тихий fallback.

Расписание событий хранится отдельно от меток посадок. Это позволяет строить прогноз для
будущих дней без будущих целевых значений. Отсутствующие часы, дубли и некорректные бинарные
значения также считаются ошибкой данных.

## Инференс и перенос в Go

Для предыдущей версии CNN реализован экспорт головы:

1. Python/PyTorch кодирует фиксированную историю каждого маршрута.
2. Постоянная часть первого линейного слоя вычисляется при сборке.
3. В JSON сохраняются параметры головы и контрольные прогнозы.
4. Go считает только календарно-зависимую часть, GELU, выходной слой и softplus.
5. Перед запуском сервер сравнивает собственный прогноз с эталоном PyTorch.

Это точное алгебраическое разложение, а не аппроксимация модели. Однако последняя CNN имеет
другие размерности (`859→320→320→24`), тогда как описание сервиса фиксирует старую голову
`685→250→24`. Экспортёр и Go-код нужно синхронно обновить, затем повторить golden-test.

## Воспроизведение модели

README ветки описывает следующую предполагаемую последовательность:

```bash
python -m venv .venv
.venv/bin/python -m pip install -e '.[test,notebook]'
.venv/bin/python -m pytest -q

python -m tram_forecast check-config --config configs/default.json
python -m tram_forecast prepare --regime validation --artifact outputs/prepared/validation_boardings
python -m tram_forecast train --artifact outputs/prepared/validation_boardings
python -m tram_forecast evaluate \
  --checkpoint outputs/runs/validation/boarding_only/best.pt \
  --artifact outputs/prepared/validation_boardings \
  --output outputs/metrics.json
```

Однако на вершине `origin/feature/cnn` эти команды сейчас не воспроизводимы: entry point
`tram-forecast` и `python -m tram_forecast` импортируют `tram_forecast.cli`, а файла
`src/tram_forecast/cli.py` в дереве нет. В README также перечислены отсутствующие модули
`config.py`, `checkpoint.py`, `smoke.py` и `io.py`. После выбора чекпойнта предполагались
final prepare, refit и predict на шаблон соревнования, но сначала нужно восстановить и
проверить CLI-контракт либо заменить инструкции прямыми вызовами существующих модулей.

## Ограничения

- Последняя модель пока не обслуживается существующей Go-головой.
- Текущая вершина ветки не запускает документированный CLI из-за отсутствующего модуля.
- Чекпойнты предыдущей архитектуры несовместимы и требуют переобучения.
- История одного года не позволяет оценить межгодовой тренд.
- Маршрут 5 не представлен в обучении.
- Событийные признаки полезны только тогда, когда расписание известно заранее и имеет
  симметричное покрытие обучения и прогноза.
- Опубликованный score подтверждает качество сабмита, но не заменяет повторяемый отчёт с
  конфигурацией, checksum чекпойнта и логом обучения. Эти сведения стоит добавить в релиз.
