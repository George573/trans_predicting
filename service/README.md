# Сервис прогноза посадок

Go-сервис, который на каждый запрос считает почасовой прогноз посадок по десяти трамвайным
маршрутам, применяет к нему сценарные условия (дождь, температура, событие, задержка,
отмена, изменение маршрута) и возвращает прогноз с коридором, обычным уровнем и аудитом
каждого условия. Кэша ответов и прекомпьюта нет: модель вызывается на каждый запрос.
Python и torch в рантайме нет, в контейнере только Go-бинарник и `libcatboostmodel`.

Контракт - `api/openapi.yaml`, поведение - `docs/SPEC-service.md`, термины - `CONTEXT.md`.

## Две модели

Обе модели равноправны: любая точка, которая считает прогноз, принимает поле
`"model": "catboost" | "cnn"`, по умолчанию `catboost`. Условия, коридор, обычный уровень,
разбор точки и выгрузка работают одинаково для обеих.

| | CatBoost | CNN |
|---|---|---|
| Что это | профильная модель без лагов: маршрут, час, календарь | сеть с контекстом 14 суток истории |
| Область дат | 2025-01-01 ... 2026-04-30 | 2025-11-01 ... 2025-12-31 (61 сутки) |
| Что считается при сборке бандла | модель `model.cbm` | контекст истории до 2025-11-01, закодированный torch |
| Что считается на запрос | деревья через `libcatboostmodel` (cgo) | голова сети в Go по каждой паре маршрут x день |
| Постобработка | калибровка маршрут x день недели, новогодние множители на 29-31 декабря | нет |
| Качество | WAPE-score вне обучения 0.8929 (фолды 3 и 4, до калибровки) | 0.88499 на лидерборде при нулевом маршруте 5 |
| Маршрут 5 | городская доля | городская доля |

Маршрут 5 истории не имеет ни у одной модели. Его значения - сумма девяти остальных маршрутов,
умноженная на долю 0.0065 / (1 - 0.0065), то есть 0.65% посадок сети. В ответе при этом
приходит предупреждение `route_without_history`.

## Запуск

Локально, из `service/`. Нужны Go 1.24 и `libcatboostmodel` той же версии, что у бандла:

```bash
bash scripts/fetch_libs.sh
go run ./cmd/server -auth jury:secret
```

Сервер слушает `:8080`, бандлы берёт из `../artifacts/bundle`, календари из
`../input/calendar`, геометрию из `../web/geo/routes.geojson`. Флаги:

| Флаг | По умолчанию | Что |
|---|---|---|
| `-addr` | `:8080` | адрес HTTP |
| `-bundle` | `../artifacts/bundle` | `conditions.json` и папки `catboost/`, `cnn/` |
| `-calendar` | `../input/calendar` | производственные календари 2024-2026 |
| `-geo` | `../web/geo/routes.geojson` | линии маршрутов для карты |
| `-auth` | пусто | basic auth `логин:пароль`; пусто - без авторизации |
| `-static` | пусто | папка собранного интерфейса с `index.html`, иначе сервер не стартует; отдаётся на `GET /`, неизвестный путь получает `index.html` |

Всё, кроме `/healthz`, закрыто basic auth, если задан `-auth`.

В контейнере, из корня репозитория:

```bash
docker compose up -d --build                                # http://127.0.0.1:8090
STAND_AUTH=jury:secret docker compose up -d --build         # то же под basic auth
```

Образ собирается в два этапа: `golang:1.24-bookworm` скачивает `libcatboostmodel` и собирает
бинарник, `debian:bookworm-slim` получает бинарник, библиотеку, бандлы, календари и
геометрию. Итоговый образ около 170 МБ, процесс работает от `nobody`.

## Бандлы

```
artifacts/bundle/
  conditions.json          каталог условий, общий для обеих моделей
  catboost/
    model.cbm              модель CatBoost
    features.json          порядок и типы признаков
    calibration.json       множители маршрут x день недели
    postprocess.json       доля маршрута 5 и новогодние множители
    corridor.json          квантили коридора и расширение по горизонтам
    meta.json              версия, период обучения, область дат, WAPE-score
    reference.csv          эталон Python на ноябрь-декабрь 2025, 14 640 строк
  cnn/
    head.json              веса головы и закодированный контекст по маршрутам и дням
    postprocess.json, corridor.json, meta.json, reference.csv   то же назначение
```

CatBoost собирается тем же кодом, что и сабмит (около 20 секунд), из корня репозитория:

```bash
uv run --quiet --python 3.12 --with catboost==1.2.10 --with polars --with 'pandas<3' \
  --with numpy --with pyarrow --with openpyxl python export_bundle.py
```

CNN собирается из чекпойнта сети. Нужен код сети из ветки `feature/cnn`
(`git worktree add ../cnn origin/feature/cnn`) и её `dataset/parking_events_hourly.csv`;
чекпойнт в git не лежит:

```bash
PYTHONPATH=../cnn/src uv run --quiet --python 3.12 --with torch --with tqdm \
  --with catboost==1.2.10 --with polars --with 'pandas<3' --with numpy --with pyarrow \
  python export_cnn_bundle.py --checkpoint cnn_14days_v9_events_final.pt \
  --events ../cnn/dataset/parking_events_hourly.csv --validation-out ../cnn_validation.pt
```

Экспортёр CNN сначала обучает валидационную модель (для коридора, см. ниже), затем прогоняет
энкодер истории на torch и раскладывает первый слой головы: всё, что не зависит от даты
запроса, считается один раз и попадает в `head.json`. Обучение на MPS недетерминировано,
поэтому повторный экспорт меняет `corridor.json`. `--validation-checkpoint` переиспользует
уже обученную валидационную модель.

При старте сервер проверяет каждый бандл и не запускается, если проверка не прошла:

- в папке есть все обязательные файлы и JSON разбирается; `meta.json` содержит версию,
  режим `service`, непустую область дат и допуск сверки;
- коэффициенты калибровки лежат в своих пределах, полосы часов коридора покрывают сутки без
  пересечений, расширение задано для каждого горизонта, доля маршрута 5 в (0, 1);
- весь `reference.csv` пересчитывается в Go и сверяется с эталоном Python: сырой выход
  модели с допуском из `meta.json`, итог после калибровки, маршрута 5 и новогоднего блока -
  с точностью до одной посадки. В журнале при старте видно, на скольких строках прошла
  сверка.

SHA-256 и размер каждого файла бандла отдаются в `/api/v1/model`.

## API

Полный контракт - `api/openapi.yaml`.

```
POST /api/v1/forecast                          прогноз с условиями
POST /api/v1/forecast/export?format=csv|xlsx   тот же прогноз файлом
POST /api/v1/explain                           путь одного значения: route, date, hour
GET  /api/v1/conditions                        каталог условий с паспортами и кривыми
GET  /api/v1/routes                            маршруты, названия, есть ли геометрия
GET  /api/v1/model                             обе модели: версии бандлов, метаданные, файлы
GET  /api/v1/stats                             счётчики запросов, строк, задержки, CPU, память
GET  /geo/routes.geojson                       линии маршрутов
GET  /healthz                                  без авторизации, версии бандлов обеих моделей
```

- `model` в теле прогноза, выгрузки и разбора выбирает модель. Дата вне области выбранной
  модели - ошибка 400 `out_of_domain` с именем модели в сообщении.
- `explain` принимает необязательные `horizon` (по умолчанию `day`) и `model` и возвращает
  шаги: сырой выход модели, обрезка нуля, калибровка, новогодний блок, каждое условие,
  коридор корректировки. Для маршрута 5 модель не вызывается ни у CatBoost, ни у CNN:
  `features` пуст, шаги начинаются со строки `маршрут 5` (городская доля).
- Выгрузка: колонки `route;date;hour;base;factor;prediction;lo;hi` (по суткам без `hour`,
  `lo;hi` только с коридором). В XLSX второй лист `Условия` с аудитом условий. Имя файла
  вида `forecast_catboost_2025-11-11_r7.csv`.
- Пределы: по часам не больше 31 суток, не больше 16 условий, не больше 50 000 строк
  прогноза на запрос (без пересчёта обычного уровня; `meta.rows` учитывает и этот пересчёт),
  тело запроса не больше 1 МБ. Ошибки - `{"error": {"code", "message", "field"}}`,
  сообщение на русском и пригодно к показу.
- Каждый ответ прогноза несёт `meta.timings` (разбор, признаки, модель, условия и коридор) и
  заголовок `Server-Timing` с теми же величинами плюс время сериализации JSON.

## Условия

Каталог и паспорта - `artifacts/bundle/conditions.json`, отдаётся через `/api/v1/conditions`.

- **Кривая.** Значение условия в единицах паспорта (мм/ч, градусы отклонения, проценты,
  доля отмены) переводится в эффект в процентах по кусочно-линейной кривой `curve`; повтор
  x - ступенька, за краями берётся крайняя точка. Например, дождь: до 0.05 мм/ч эффекта нет,
  дальше ступеньки по измеренным классам интенсивности.
- **Паспорт маршрута.** Если область условия - ровно один маршрут и для него есть свой
  измеренный эффект, кривая масштабируется на отношение маршрутного эффекта к общему и в
  ответ уходит паспорт маршрута. Иначе действует общий паспорт.
- **Композиция и коридор корректировки.** Условия на одной точке перемножаются, порядок не
  важен. Произведение ограничено коридором корректировки из каталога; если ограничение
  сработало, в ответе приходит предупреждение `correction_clamped` с числом часов, а в
  разборе - шаг `коридор корректировки`.
- **Горизонты.** Дождь, температура и событие действуют на горизонтах день и неделя,
  задержка - только на горизонте день. На других горизонтах такое условие сохраняется в ответе
  с `applied: false` и предупреждением и прогноз не меняет. Структурные условия (отмена,
  изменение маршрута) действуют на всех горизонтах.
- **Событие на CNN.** В признаках CNN уже есть запланированные события рядом с маршрутом и
  городские события. Условие `event` на дату, которую сеть и так знает как событийную, может
  учесть эффект дважды. У CatBoost событий в признаках нет.

**Ни одно условие не применяется автоматически.** Это измеренное решение: автоматическая
поправка на дождь двигает почасовой WAPE на +0.013 пункта [-0.044; +0.065], то есть ни на
что, а фиксированные температурные коэффициенты делают прогноз хуже. **При этом сами эффекты
реальны и значимы на истории**: дождливых часов всего около 10%, а норма и без погоды
ошибается в дневные часы в среднем на 10% посадок, поэтому на общей метрике эффект тонет.
Условия - инструмент сценария, а не скрытая поправка.

## Коридор и обычный уровень

**Коридор** (`lo`, `hi`) показывает, в каком диапазоне обычно оказывается факт вокруг прогноза.
Он строится по прогнозам каждой модели вне обучения:

- CatBoost - предсказания фолдов 3 и 4 (обучение до 2025-08-31 и до 2025-09-30, прогноз на
  сентябрь-октябрь и октябрь);
- CNN - собственная валидационная модель: обучена тем же рецептом по 2025-08-31 и прогнозирует
  61 сутки с 2025-09-01, её WAPE-score 0.8205. Она слабее финальной модели, поэтому коридор
  CNN скорее шире, чем нужно.

Берутся квантили 0.1 и 0.9 отношения факта к прогнозу: по часам - в группах маршрут x полоса
часов (ночь, утро, день, вечер), по суткам - по маршруту, с общим запасным значением `*`.
Каждую пару квантилей маршрута делят на медиану суточного отношения факта к прогнозу этого
маршрута (`*` - на общую медиану), а затем ограничивают так, чтобы коридор всегда содержал
прогноз. Так коридор несёт только разброс, а уровень задают модель и калибровка.

Ширина растёт с горизонтом. Коэффициенты расширения монотонны: день равен неделе, дальше
берётся нарастающий максимум по неделе, месяцу и сезону. Кроме того, полуширина коридора не
меньше 20% на горизонте месяц и 30% на горизонте сезон: это классы «плановый» и «незнакомый
режим» из `docs/RESEARCH-horizon.md`.

Известные ограничения:

- в коридоры маршрутов 7 и 50 вошли ограничения движения августа-октября 2025, которые
  пришлись на период вне обучения, поэтому у маршрута 50 нижняя суточная граница близка к 0;
- ночные коридоры широкие в относительных величинах: ночью посадок мало, и небольшое
  абсолютное отклонение даёт большой процент.

**Обычный уровень** (`usual`) - прогноз той же модели на ту же дату и час, как если бы день
был обычным днём своего дня недели: без праздников, сокращённых дней и предпраздничных
признаков (у CNN - и без событий), с калибровкой, но без новогодних множителей и без
условий. Карта красит линию по `value / usual`: процент от обычного уровня.

## Производительность

Нагрузку даёт `cmd/load` по смеси запросов из `scripts/gen_load.py`: 4000 тел, модель
CatBoost или CNN поровну; 60% - один маршрут на сутки по часам, половина с дождём на
16-22 ч; 20% - вся сеть на сутки по часам, половина с дождём; 15% - один маршрут на 30 суток
по дням, горизонт месяц; 5% - вся сеть на 30 суток по часам. В среднем около 600 строк модели
на запрос, средний ответ 8.8 КБ.

```bash
cd service
uv run --quiet --python 3.12 python scripts/gen_load.py > bodies.jsonl
go build -o bin/server ./cmd/server && go build -o bin/load ./cmd/load
./bin/server -addr :18080 &
./bin/load -url http://localhost:18080/api/v1/forecast -bodies bodies.jsonl -c 8 -d 5s -label "прогрев"
curl -s localhost:18080/api/v1/stats
./bin/load -url http://localhost:18080/api/v1/forecast -bodies bodies.jsonl -c 8 -d 15s -label "8 потоков"
curl -s localhost:18080/api/v1/stats
./bin/load -url http://localhost:18080/api/v1/forecast -bodies bodies.jsonl -rate 500 -c 64 -d 15s -label "500 RPS"
curl -s localhost:18080/api/v1/stats
```

Машина: Apple M4 (10 ядер), macOS, сервер без контейнера, `GOMAXPROCS=10`, генератор на той
же машине. Перед замерами 5 секунд прогрева теми же запросами, каждый замер 15 секунд.
Задержка - от отправки запроса до конца ответа на стороне клиента. CPU - `cpu_pct` из
`/api/v1/stats` за время замера, в процентах одного ядра: `cpu_pct` считается с предыдущего
вызова `/stats`, поэтому он вызывается до и после каждого замера (сервер запущен без `-auth`,
с авторизацией нужен `curl -u логин:пароль`).

| Сценарий | RPS | p50, мс | p95, мс | p99, мс | Ошибки | CPU |
|---|---:|---:|---:|---:|---:|---:|
| 8 потоков, замкнутый цикл | 2 544 | 0.64 | 10.92 | 48.52 | 0 | 599% |
| 500 RPS, открытый цикл | 500 | 0.61 | 7.68 | 31.49 | 0 | 95% |

- Хвост p95-p99 дают тяжёлые запросы по всей сети на 30 суток по часам: около 6 500 строк
  модели на запрос против 24-720 у остальных.
- Между повторами пропускная способность на этой машине колебалась в пределах 15%.
- Прод - 2 vCPU Xeon: он заметно медленнее, и на 8 потоках упирается в два ядра. 500 RPS
  этой смеси занимают на M4 около одного ядра.
- Тяжёлые запросы - вся сеть одной моделью с коридором и без условий. Время на сервере
  по `Server-Timing`, медиана пяти повторов после прогрева, M4:

  | Запрос | CatBoost, мс | CNN, мс |
  |---|---:|---:|
  | 30 суток по часам, 2025-11-01...2025-11-30 | 8 | 29 |
  | 61 сутки по суткам, 2025-11-01...2025-12-31 | 14 | 56 |

  Почти всё это время уходит на саму модель. В смеси нагрузки запрос к CNN стоит примерно в
  2.4 раза больше CPU, чем запрос к CatBoost; на проде (2 vCPU) ни смесь, ни эти запросы не
  замерялись.
- `cmd/load` с `-pid` дополнительно замеряет CPU и память процесса через `/proc`, то есть
  только на Linux; на macOS эти поля нулевые, поэтому CPU в таблице взят из `/api/v1/stats`.

## Два факта о метриках рядом

1. **CatBoost дашборда - это сервисный бандл без погоды.** CSV, отправленный на платформу,
   собран метрической конфигурацией, где погода - признаки модели. Разница на целевой
   метрике - 0.198 пункта в пользу метрической: 0.88466 против 0.88268. В сервисе погода
   приходит условием, а не признаком, иначе её эффект считался бы дважды.
2. **Ни одно условие не применяется автоматически**, хотя эффекты реальны: автоматическая
   поправка на дождь двигает почасовой WAPE на +0.013 пункта [-0.044; +0.065], фиксированные
   температурные коэффициенты делают хуже, а при этом дождливых часов около 10%, и норма и так
   ошибается в дневные часы примерно на 10% посадок.

## Отклонения от `docs/SPEC-service.md`

- Две модели вместо одной и поле `model` в запросах; `/api/v1/model` отдаёт
  `{default, models: [...]}` с описанием и файлами каждой модели, `/healthz` - версии обеих.
- Предел строк прогноза на запрос - 50 000 вместо 20 000: сезон по всей сети по суткам -
  181 x 9 x 24 = 39 096 строк. Предел не учитывает пересчёт обычного уровня для необычных
  дней, а `meta.rows` учитывает, поэтому в ответе бывает больше 50 000.
- XLSX собирается стандартной библиотекой (`archive/zip`), без `excelize`: для простой
  таблицы нужно пять XML-частей, зависимость не нужна.
- Коридор считается по собственным прогнозам вне обучения каждой модели, а не по
  `oof_pooled.parquet`.
- Метрический бандл (погода признаками) не экспортируется: сервис его никогда не читает.
- `explain` принимает необязательные `horizon` и `model` и возвращает `model`, `conditions`
  и `warnings`.
- Файл модели CatBoost - `model.cbm` в `artifacts/bundle/catboost/`, а не `model_service.cbm`.
- `meta.wape_score` бандла CatBoost - это 1 - WAPE моделей фолдов 3 и 4 до калибровки, а не
  WAPE отдаваемого откалиброванного прогноза.
- `meta.wape_score` бандла CNN - это 1 - WAPE валидационной модели на 61 сутках с 2025-09-01
  (0.8205), а не 0.88499 финальной модели на лидерборде.
- Расширение коридора по горизонту не берётся напрямую из сравнения фолдов: квантили
  центрируются на медиане каждого маршрута, расширение монотонно, а минимальная полуширина
  взята из `docs/RESEARCH-horizon.md` (см. «Коридор и обычный уровень»).
- В образе нет файлов интерфейса, и контейнер запускается без `-static`: сервер в нём отдаёт
  только API.
- Неизвестный путь и неверный метод получают текстовые 404 и 405 вне формата ошибок
  `{"error": ...}`.
