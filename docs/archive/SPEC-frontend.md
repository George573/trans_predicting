# Спека: дашборд прогноза (фронтенд)

Спека самодостаточна: её должно быть достаточно, не читая остальную переписку. Термины -
[CONTEXT.md](../CONTEXT.md), контракт бэкенда - [SPEC-service.md](./SPEC-service.md),
макеты - канвас `https://claude.ai/artifact/TTg2r7zyFGi9NFNYXa1hnM` (доски F1-F4, D1-D8,
компоненты T, G, M, R, U, K, S).

## Problem Statement

В Едином диспетчерском центре прогноз пассажиропотока строят на простых регрессиях и
смотрят в выгрузках. Нужно рабочее место, где диспетчер видит прогноз посадок по маршрутам
на четырёх горизонтах, может задать условия («пойдёт дождь», «перекроют участок») и сразу
увидеть, как изменился прогноз, и может выгрузить результат.

## Solution

SPA на React 19 и TypeScript 5, сборка Vite в статику. Статика отдаётся тем же Go-бинарником,
что и API: один контейнер, никакого Node в продакшене. Кэша на бэкенде нет сознательно -
каждое действие в интерфейсе отправляет настоящий запрос и получает свежий прогноз за
единицы миллисекунд. Это часть демонстрации: время запроса показывается в интерфейсе.

## Стек и ограничения

- React 19, TypeScript 5, Vite. Сборка в `dist`, её забирает Go-бинарник.
- Карта - **Leaflet** по статичному GeoJSON из репозитория (`web/geo/routes.geojson`).
  Подложка OSM опциональна и деградирует: контейнер должен осмысленно работать без
  интернета, линии рисуются и без тайлов.
- Графики - любая лёгкая библиотека (uPlot, Recharts) или собственный SVG. Требование одно:
  744 точки (месяц по часам) рисуются без заметной задержки.
- Состояние - без тяжёлых менеджеров: `useReducer` на один объект запроса плюс кеш
  последнего ответа. Запрос - единственный источник истины, интерфейс из него выводится.
- Русский язык интерфейса. Тёмная диспетчерская тема как на досках C и D8.

## Контракт с бэкендом

**Машиночитаемый контракт - [api/openapi.yaml](../api/openapi.yaml), OpenAPI 3.1.**
Из него генерируются типы (`openapi-typescript` или аналог) - руками их не писать.
Готовые примеры ответов для работы без бэкенда: `api/examples/forecast-day.json`
(сутки по часам, применённое условие с почасовым профилем) и
`api/examples/forecast-month.json` (месяц по суткам, отложенное условие и два
предупреждения). Оба проверены по схеме.

Один основной запрос. Basic auth, кроме `/healthz`.

```
POST /api/v1/forecast
{
  "routes": [7, 11],            // пусто = все десять
  "from": "2025-11-10",
  "to":   "2025-11-16",
  "granularity": "hour",        // hour | day
  "horizon": "week",            // day | week | month | season
  "corridor": true,
  "conditions": [
    { "id": "c1", "type": "rain", "value": 1.2,
      "scope": { "routes": [7], "dates": ["2025-11-11"], "weekdays": null, "hours": [16, 22] } }
  ]
}
```

Ответ:

```
{
  "start": "2025-11-10T00:00", "step": "1h", "bundle": "...",
  "series": [ { "route": 7,
                "base": [...],   // до условий
                "value": [...],  // после условий
                "lo": [...], "hi": [...],   // коридор
                "usual": [...],  // обычный уровень для этого маршрута, дня недели и часа
                "base_total": 120431, "total": 118903, "peak_index": 18 } ],
  "conditions": [ { "id": "c1", "type": "rain", "applied": true, "factor": 0.936,
                    "contribution_pct": -1.4, "points": 7,
                    "profile": null,        // почасовой профиль эффекта, только для 1 маршрут + 1 сутки
                    "passport": { "unit", "source", "source_url", "effect_pct", "ci_pct",
                                  "sample", "horizons", "class" } } ],
  "warnings": [ { "code", "condition_id", "message" } ],
  "meta": { "rows": 336, "model": "...", "timings": { ... } }
}
```

Остальное:

```
POST /api/v1/forecast/export?format=csv|xlsx   тело как у forecast, ответ - файл (blob)
POST /api/v1/explain                           одна клетка: route, date, hour, conditions
GET  /api/v1/conditions                        каталог условий с паспортами
GET  /api/v1/routes                            маршруты, названия, есть ли геометрия
GET  /api/v1/model                             версия бандла и метаданные обучения
GET  /api/v1/stats                             счётчики, CPU, память
GET  /healthz
```

- Время точки `i` = `start + i * step`. Все серии одной длины.
- Ошибки: `{"error": {"code", "message"}}` с готовым к показу русским текстом, коды 400,
  401, 413, 500. Показывать `message`, а не «что-то пошло не так».
- Пределы: `granularity=hour` не больше 31 суток, условий не больше 16, диапазон дат
  2025-01-01 ... 2026-04-30. Превышение - 413 с понятным сообщением.
- Заголовок `Server-Timing` содержит разбивку времени; её же дублирует `meta.timings`.

## Экраны

Один экран, четыре горизонта, две раскладки. Колонка управления слева, рабочая область
справа. Раскладки: «карта плюс графики» (по умолчанию, доска D1) и «мозаика 2x2» (доска D7,
без главной карты). Переключатель раскладки - в колонке управления.

| Горизонт | Доска | Квант | Ось периода | Условия |
|---|---|---|---|---|
| День | F1 | час | 24 часа, ночные часы свёрнуты | оперативные и структурные |
| Неделя | F2 | сутки, часы вложенно | 7 суток | оперативные и структурные |
| Месяц | F3 | сутки | календарная сетка | только структурные |
| Сезон | F4 | месяц | ноя 2025 - апр 2026 | только структурные |

Горизонт «Год» из макета становится «Сезоном»: подпись, длина полосы - шесть месяцев, всё
остальное поведение сохраняется. Панель «ширина коридора по месяцам» остаётся: она честно
показывает деградацию точности.

Блоки колонки управления, сверху вниз: **объект** (сеть или маршрут, список маршрутов с
худшим значением), **период** (горизонт, навигация по датам, выбор часа), **условия**,
**вид**, **чего модель не считает**.

Рабочая область: **карта сети или маршрута**, **график прогноза** по выбранному кванту,
**цифры и решения**, **тревоги**.

## Пересчёт терминов макета

Макеты рисовались, когда предполагалось считать заполнение салона. Мы этого не делаем:
посадка - это валидация, и пассажир, едущий три остановки, и пассажир, едущий весь маршрут,
дают по одной. Поэтому часть подписей заменяется, и это не косметика - это то, что нельзя
перепутать.

| В макете | Что показываем на самом деле |
|---|---|
| Заполнение 99%, «до 40% / 40-70% / более 70%» | **% от обычного уровня** для этого маршрута, дня недели и часа: `value / usual` |
| Провозная способность, спрос выше вместимости | не показываем, линию с графика убрать |
| Вагонов в пик 10 / 12, «нужно +2 вагона» | панель убрать целиком |
| Заполнение выше порога (тревоги) | **выше верхней границы коридора** - `value > hi` |
| «Заполнение - оценка: расписание + вместимость» | подпись убрать |
| 9 маршрутов с историей, маршрут 5 пустой | **10 маршрутов**; маршрут 5 подписан «оценка»: истории нет, значение получено городским профилем |

Слова **загрузка**, **пассажиропоток**, **наполнение**, **заполнение салона** в интерфейсе
не употребляются. Величина везде называется **посадки в час** (или в сутки, в месяц - по
кванту). В легенде карты обязательна подпись «% от обычного уровня», иначе показатель
читается как заполнение вагона.

## Условия

Два класса, и они разделены в интерфейсе в два списка, а не в один.

- **Оперативные**: дождь, температура, событие, задержка. Эффект - множитель в единицы
  процентов. Доступны на дне и неделе. Период сценария не больше 7 суток.
- **Структурные**: отмена или перекрытие, изменение маршрута. Меняют сеть, а не уровень.
  Доступны на всех горизонтах, включая сезон.

**Карточка условия** (доска U3) несёт тип, значение в реальных единицах, область («где» и
«когда») и показывает эффект в процентах как подсказку, а не как поле ввода. Значение
задаётся ползунком в границах измеренного интервала из паспорта - не произвольным числом.

**Паспорт** (U10) показывается при наведении и в каталоге: единица и шаг, источник со
ссылкой, измеренный эффект с границами, объём выборки, допустимые горизонты. Это главный
аргумент на защите: величина измерена на истории, а не придумана.

**Область условия по горизонтам:**

- День: протяжка по столбцам суточного профиля (U12) плюс поля «с / по» и пресеты «утренний
  пик», «вечерний пик», «весь день» (U13).
- Неделя: полоса суток с вложенным выбором часов (U16) либо матрица «день x часть суток»
  (U17).
- Месяц: шаблон дней - «все будни», «выходные», «праздники», «свои даты» (U18) - или
  непрерывный диапазон дат ползунком (U19). **Шаблон разворачивается в явный список дат на
  клиенте перед отправкой**: сервер шаблонов не понимает.
- Сезон: отрезки на полосе месяцев (U20).

**Пересечение условий** (U15) показывается явно: на пересекающихся часах видно оба условия
и их произведение. Условия перемножаются, порядок не важен.

**Переключение горизонта с заданными условиями:** условия **сохраняются, но не
применяются**. Сервер вернёт их с `applied: false` и предупреждением. Интерфейс показывает
баннер «2 условия не применимы на горизонте месяц» и держит карточки серыми. При возврате на
день они снова работают, вместе с почасовой областью. Ни схлопывания области, ни блокировки
переключателя горизонта.

**Пустое состояние вместо скрытия** (U11): на месяце и сезоне блок «условия» не исчезает.
Он показывает объяснение - измеренный эффект оперативного условия меньше ширины коридора -
и список структурных условий, которые здесь осмысленны.

**Сезон как заблокированный контрол** (U22, U26): строка «сезон: зима, учтён моделью» с
заблокированным контролом. То же для погоды на месяце и сезоне: значение климатической нормы
видно, ползунок заблокирован. Это не заглушка, а утверждение: множитель поверх модельного
признака считал бы эффект дважды.

## Аудит

Из одного ответа рисуются три вещи, второй запрос не нужен:

- **Таблица факторов** (U5): фактор, источник, значение, вклад. Берётся из
  `conditions[].passport` и `contribution_pct`.
- **Разложение вклада** (U7): «обычный день, затем с условиями» - из `base_total` и `total`
  плюс вклад каждого условия.
- **Профиль эффекта по часам** (U14): только когда выбран один маршрут и одни сутки, из
  `conditions[].profile`. В остальных случаях поле `null` - панель не показывается.

Клик по столбцу графика или клетке тепловой карты отправляет `/api/v1/explain` и показывает
весь путь одной точки: календарь, признаки в том виде, в каком они ушли в модель, сырой
выход, обрезку нуля, калибровку, каждое условие отдельной строкой, итог.

## Карта

- Линии десяти маршрутов из статичного GeoJSON. Цвет линии - процент от обычного уровня в
  выбранный момент. Выбранный маршрут подсвечен, у остальных номеров - худшее значение.
- Остановки рисуются **только как геометрия**, без чисел и без размера по величине.
  Посадок в разрезе остановок в данных нет, придуманные доли показывать нельзя.
- Кольца превышений - там, где `value > hi`.
- Легенда: «% от обычного уровня», три полосы и подпись, что остановки - геометрия.
- Пять маршрутов из десяти пришли из справочника, пять - из OSM. Если у маршрута нет
  геометрии, он живёт в списке и графиках, а на карте отсутствует, с явной пометкой.

## Выгрузка

Кнопки CSV и XLSX. Обе отправляют `POST /api/v1/forecast/export?format=...` с тем же телом,
что текущий вид, и сохраняют полученный blob под именем из `Content-Disposition`. Выгружается
именно то, что на экране: те же маршруты, период, квант и условия.

## Состояния и производительность

- Запрос уходит на каждое изменение управления. Дебаунс ползунков 150-200 мс, предыдущий
  запрос отменяется `AbortController`.
- Панель «запрос»: адрес, статус, число строк модели, разбивка времени из `Server-Timing`
  полосой (разбор, признаки, модель, условия, JSON, сеть). Это демонстрационная ценность,
  а не отладка: её видно всегда.
- Журнал последних 12 запросов, клик по строке повторяет запрос.
- Пустое состояние, состояние загрузки (скелет, не спиннер на весь экран), состояние ошибки
  с текстом из `error.message`.
- Панель нагрузки: 1-12 параллельных потоков на 15 секунд, RPS и ресурсы из
  `/api/v1/stats`. Браузер держит не больше 6 соединений, поэтому подписать, что это оценка
  снизу, а честный замер делает нагрузочный клиент бэкенда.

## Definition of Done

1. Четыре горизонта переключаются, каждый показывает свой квант и свою полосу периода.
2. Выбор сети и отдельного маршрута; несколько маршрутов - тепловая карта маршрут x время.
3. Условия: шесть типов, два списка, область задаётся по правилам горизонта, шаблоны
   разворачиваются в даты на клиенте.
4. Переключение горизонта не теряет условия и показывает баннер.
5. Карта: десять маршрутов, цвет по проценту от обычного, остановки без чисел, легенда.
6. Аудит: таблица факторов, разложение вклада, профиль эффекта на дне, `explain` по клику.
7. Выгрузка CSV и XLSX того, что на экране.
8. Ни одного упоминания заполнения салона, вместимости и вагонов.
9. Панель времени запроса и журнал работают.
10. Сборка `dist` лежит в образе и отдаётся Go-бинарником; интерфейс работает без интернета,
    кроме подложки карты.

## Out of Scope

- Числа по остановкам, участкам и направлениям.
- Вместимость, заполнение салона, расчёт нужного числа вагонов.
- Авторизация сложнее basic auth, роли, пользователи.
- Приём потоковых данных и их отображение в реальном времени.
- Печатные отчёты и рассылки.
