# Provenance of the hourly event dataset

`dataset/parking_events_hourly.csv` is an extraction from data already produced
by this repository's pipelines on the `main` branch. Creating this file did not
collect new events, fetch external data, or recompute geographic relationships.
The extraction filtered routes and dates, selected columns, derived binary
presence flags, and joined existing parking features.

## Source snapshot

The source code and outputs were inspected in the locally available `origin/main`
snapshot at commit `a7cbd77e83bec660049cc6472f1c3e25420f5130`. This is the reference
used for verification, not a claim that the original extraction recorded that
commit. The local `main` branch is older and does not contain the `events` directory.

Source files on the main-branch snapshot:

- [events/build_events.py](https://github.com/George573/trans_predicting/blob/a7cbd77e83bec660049cc6472f1c3e25420f5130/events/build_events.py): upstream feature generation.
- [events/README.md](https://github.com/George573/trans_predicting/blob/a7cbd77e83bec660049cc6472f1c3e25420f5130/events/README.md): source links, feature definitions, and limitations.
- [events/data/events_hourly.csv](https://github.com/George573/trans_predicting/blob/a7cbd77e83bec660049cc6472f1c3e25420f5130/events/data/events_hourly.csv): existing event features, 175,200 rows covering ten routes in 2025–2026.
- [factors/data/factors_hourly.csv](https://github.com/George573/trans_predicting/blob/a7cbd77e83bec660049cc6472f1c3e25420f5130/factors/data/factors_hourly.csv): existing parking and other factors for 2025.
- [factors/README.md](https://github.com/George573/trans_predicting/blob/a7cbd77e83bec660049cc6472f1c3e25420f5130/factors/README.md): upstream parking and route-geometry provenance.

These source paths refer to the main branch; they are not present in the current
model-training checkout.

## Current file and column lineage

The current file covers **2025-01-01 through 2025-12-31**, not the source's full
2025–2026 range. It contains 78,840 rows: nine routes × 365 days × 24 hours.
The routes are `1, 7, 11, 12, 17, 25, 26, 28, 50`; route 5 is excluded.

Format: UTF-8 CSV, semicolon delimiter, one header row, sorted numerically by
route and then chronologically by date and hour. The unique key is
`route;date;hour`; dates are `YYYY-MM-DD`, hours are integers 0–23.

| Output column | Existing source | Extraction transformation |
|---|---|---|
| `route`, `date`, `hour` | Both hourly tables | Join keys; filter to the nine routes and 2025 |
| `extended_night_service` | `events_hourly.csv` | Copy the binary flag |
| `event_near_route` | `events_hourly.csv` | Copy the binary flag |
| `is_citywide_event` | `events_hourly.csv: citywide_event` | Non-null event ID → 1; null → 0 |
| `has_route_change` | `events_hourly.csv: route_change` | Non-null change kind → 1; null → 0 |
| `parking_pct_route` | `factors_hourly.csv: parking_pct_route` | Join by route/date/hour; replace missing occupancy with 0 |
| `has_parking` | Original `parking_pct_route` before filling | Non-null occupancy → 1; null → 0 |

The parking mask distinguishes an observed zero from a missing value replaced
with zero. Event IDs, categories, phases, distances, route-change kinds, and
upstream calendar columns are omitted. The model generates its calendar inputs
separately from the bundled Russian production-calendar XML.

## How the upstream event pipeline produces the flags

`events/build_events.py` builds its calendar and event catalogue, then expands
them onto an hourly grid for ten routes. It writes `calendar_daily.csv`,
`football_moscow.csv`, `events.csv`, and `events_hourly.csv`.

**Extended night service.** `extended_night_dates()` defines early-morning dates
for New Year, Christmas, Epiphany, Easter, and City Day. `hourly()` marks hours
0–3 on those dates. This is a scheduled-date rule applied to every route, not
a measurement of actual service. The daily calendar is generated by the same
script from encoded calendar rules; it is not read back as an input to this flag.
The upstream README identifies production-calendar decrees and announcement sources.

**Events near a route.** `events_table()` combines manually curated events from
`events/data/events_manual.csv` with Moscow home football matches derived from
`football_rpl_raw.csv`. Manual records include source links. Football records
come from football-data.co.uk, with kickoff times converted to Moscow time.
The script associates venues with coordinates and computes the distance to the
nearest segment of each route in `factors/data/route_lines.geojson`. Those route
geometries originate from OpenStreetMap, as documented by the factors pipeline.

In `hourly()`, an event's activity window begins two hours before its start
rounded down to the hour and ends two hours after its end, inclusively. The
nearest active event is retained. `event_near_route` is 1 when that event's
stored distance is at most 1.5 km. Distances are rounded to two decimal places
upstream. Football duration is assumed to be 110 minutes; some concert times
are approximate, as documented upstream.

**Citywide events.** Events whose venue is `citywide` or `center` populate the
`citywide_event` ID field during their event window, without the two-hour local
event padding. The extraction converts presence of that ID to a binary flag.
It does not infer event identities or recalculate event windows.

**Operational columns.** Route-change kinds are expanded from the curated
`events/data/route_changes.csv`. Parking occupancy is already aggregated in
`factors_hourly.csv` from the upstream parking data for lots within 1 km of each
route. Extraction only joins these values and constructs presence masks.

## Equivalent extraction recipe

The following reproduces the documented transformations from the main-branch
outputs. It is an equivalent recipe, not the preserved original extraction script.
Run it in a checkout containing the source files, with pandas installed.

```python
import pandas as pd

routes = (1, 7, 11, 12, 17, 25, 26, 28, 50)
keys = ["route", "date", "hour"]

events = pd.read_csv("events/data/events_hourly.csv")
events = events.loc[
    events.route.isin(routes)
    & events.date.between("2025-01-01", "2025-12-31")
].copy()
events["is_citywide_event"] = events.citywide_event.notna().astype(int)
events["has_route_change"] = events.route_change.notna().astype(int)
columns = keys + [
    "extended_night_service", "event_near_route", "is_citywide_event",
    "has_route_change",
]

factors = pd.read_csv("factors/data/factors_hourly.csv")
out = events[columns].merge(
    factors[keys + ["parking_pct_route"]],
    on=keys, how="left", validate="one_to_one", indicator=True,
)
assert out["_merge"].eq("both").all()
out = out.drop(columns="_merge")
out["has_parking"] = out.parking_pct_route.notna().astype(int)
out["parking_pct_route"] = out.parking_pct_route.fillna(0.0)
out = out.sort_values(keys).reset_index(drop=True)

assert len(out) == 9 * 365 * 24
assert not out.duplicated(keys).any()
assert not out.isna().any().any()
assert out.groupby("route").size().eq(365 * 24).all()
for name in [
    "extended_night_service", "event_near_route", "is_citywide_event",
    "has_route_change", "has_parking",
]:
    assert out[name].isin([0, 1]).all()

out.to_csv("dataset/parking_events_hourly.csv", sep=";", index=False)
```

## Verification and model use

The current file was checked against the source snapshot by key. There were
zero mismatches for all six derived feature columns under the transformations
above. All 78,840 keys are unique, each route has 8,760 rows, and all columns
have zero empty values. The three scheduled flags are binary.

The model reads only `extended_night_service`, `event_near_route`, and
`is_citywide_event`. Historical inputs preserve their hourly values; target-day
inputs use the maximum across each day's 24 hours. Route-change and parking
columns are excluded entirely, including from history.

The source catalogue is not an exhaustive event calendar. More importantly,
the upstream README states that some November–December 2025 and 2026 announcements
were collected from sources published after 31 October 2025. A scheduled event
can be knowable in advance, but this retrospective catalogue does not establish
that every included record was available at a particular historical forecast
cutoff. Strict historical evaluation needs announcement-time filtering.
