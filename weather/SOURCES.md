# Источники погоды для Москвы: 2024-01-01 .. 2026-12-31

Все проверки в этом файле выполнены вживую 26.09.2026 по точке 55.75, 37.62
(и по станциям WMO 27612 ВДНХ, 27605 Балчуг, ICAO UUEE Шереметьево).
Для каждого источника приведён реальный HTTP-код и фрагмент реального ответа.
Полные выгрузки не качались: только короткие пробы.

Дополняет `data/README.md` - инвентарь того, что собрано в репозитории за 2024-2026 годы.

## 1. Короткое резюме: что брать в первую очередь

Почасовой ряд на весь требуемый период закрывается одним источником:

**Open-Meteo Historical Forecast API** отдаёт непрерывный почасовой ряд
с 2024-01-01 по «сегодня + 15 суток» одним запросом. Проверено:
24 360 часов (2024-01-01T00:00 .. 2026-10-11T23:00), ноль пропусков,
ответ 580 КБ. В нём есть ровно те переменные, которые интересны для
пассажиропотока: `snow_depth`, `snowfall`, `weather_code`,
`apparent_temperature`, а не только температура.

Порядок приоритетов:

1. **Open-Meteo Historical Forecast API** - базовый почасовой ряд
   2024-2026 плюс 15 суток вперёд, без лага и без дыр.
2. **Open-Meteo Archive API, `models=ecmwf_ifs`** - альтернативный
   почасовой ряд с 2017 года, тоже доходит до текущих суток (9 км).
   `models=era5` берём только как климатический эталон: у него лаг
   5 суток, и хвост 2026 года он не закрывает.
3. **rp5.ru** - станционный факт Росгидромета: 8 сроков в сутки,
   текстовые явления погоды (`WW`) и высота снега (`sss`). Единственный
   из проверенных источников, который даёт высоту снега по станции
   в Москве за 2024-2026.
4. **Meteostat bulk** - почасовые METAR аэропортов, обновляется каждый
   день, плюс колонка `coco` (код условий погоды) и `wpgt` (порывы).
5. **Iowa Environmental Mesonet ASOS** - METAR каждые 30 минут,
   с `wxcodes` (явления) и `feel` (ощущаемая температура).
6. Для будущего периода вместо прошлогодних значений: **Open-Meteo
   Forecast API** (16 суток почасово), **Ensemble API** (16 суток,
   39 членов), **Seasonal API** (до 7 месяцев, посуточно, 50 членов).

Что ломается на границах периода:

- **2024 год:** Previous Runs API не покрывает начало января 2024.
  ICON и GFS начинаются между 18 и 22 января 2024, ECMWF IFS 0.25 -
  с 4 февраля 2024 (в собранном файле первое непустое значение по
  ВДНХ - 2024-02-04T03:00, по точке 55.75/37.62 - 2024-02-05).
  Первые недели 2024 года прогнозными признаками закрыть нельзя,
  нужен Historical Forecast API.
- **2026 год:** NOAA ISD по российским станциям оборвался 24.08.2025,
  файлов за 2026 год там нет вообще. ERA5 отстаёт на 5 суток.
  Свежий хвост 2026 года дают только rp5, Meteostat, IEM, Ogimet,
  NASA POWER (лаг 3 суток) и Open-Meteo `ecmwf_ifs` /
  historical-forecast.

## 3. Источники по отдельности

### 3.1 Open-Meteo Historical Forecast API - основной источник

Что это: архив первых часов последовательных прогонов оперативных
моделей, сшитый в непрерывный почасовой ряд. По документации он
«closely tracks actual conditions because each run is initialised from
real measurements», то есть это не реанализ, а восстановленный «почти
факт» без лага ERA5.

Запрос:

```
https://historical-forecast-api.open-meteo.com/v1/forecast
  ?latitude=55.75&longitude=37.62
  &start_date=2024-01-01&end_date=2026-10-11
  &hourly=temperature_2m,relative_humidity_2m,apparent_temperature,
          precipitation,snowfall,snow_depth,weather_code,pressure_msl,
          wind_speed_10m,wind_direction_10m,wind_gusts_10m,cloud_cover
  &timezone=Europe/Moscow&wind_speed_unit=ms
```

Проверка:

- HTTP 200, 24 360 часов, `2024-01-01T00:00` .. `2026-10-11T23:00`,
  пропусков ноль, размер ответа 579 059 байт.
- Границы диапазона источник сообщает сам: при `end_date=2026-12-31`
  отвечает HTTP 400, `"Parameter 'end_date' is out of allowed range
  from 2016-01-01 to 2026-10-11"`.
- Хвост действительно прогнозный и заполнен: на 2026-10-05T12:00
  `temperature_2m` 11.7, `weather_code` 2, `snow_depth` 0.0,
  `apparent_temperature` 9.4.
- Зима 2024 выглядит правдоподобно: 2024-01-01T00:00 температура -9.8,
  `snow_depth` 0.19 м, `weather_code` 71 (слабый снег).

Почему это важно: 2026-12-31 недостижим ни у одного бесплатного
источника фактической погоды, максимум - «сегодня + 15 суток».
Дальше только прогноз (см. 3.8) или прошлогодние значения.

### 3.2 Open-Meteo Archive API (ERA5 и родственники)

Эндпоинт `https://archive-api.open-meteo.com/v1/archive`,
параметр `models`.

- `models=era5`. HTTP 200 на 2024-01-01: температуры -10.8 .. -16.5,
  `snowfall` заполнен, `weather_code` 3, `apparent_temperature` -17.2.
  Диапазон, который сообщает сам API: `from 1940-01-01 to 2026-09-26`,
  но фактические значения кончаются на `2026-09-21T02:00` MSK
  (= 2026-09-20 23:00 UTC): за 2026-09-01..26 непусты 483 часа из 624.
  Это ровно документированный лаг ERA5T в 5 суток. Независимая
  проверка: метаданные ARCO-ERA5 в тот же день сообщают
  `"valid_time_stop_era5t": "2026-09-20"` и
  `"valid_time_stop": "2026-06-30"` (финальный ERA5 отстаёт на 3 месяца).
- `models=era5` не отдаёт `snow_depth`: за 2024-01-15 все 24 часа пусты,
  при этом `snowfall`, `weather_code` и `apparent_temperature`
  заполнены полностью.
- `models=era5_land` (11 км) отдаёт `snow_depth`: за 2024-01-15
  все 24 часа заполнены, значение 0.58 м. Но `snowfall` и
  `snow_depth_water_equivalent` у него пусты. Лаг тот же, 2026-09-21T02.
- `models=era5_seamless` по значениям совпадает с `era5_land` там, где
  ERA5-Land есть (2026-09-21T02: 15.4 против 14.5 у чистого ERA5),
  то есть это ERA5-Land с откатом на ERA5, а не «ERA5 плюс прогноз»:
  лаг он не сокращает.
- `models=ecmwf_ifs` (9 км, с 2017 года) - находка: за 2026-09-01..26
  заполнены все 624 часа, последнее значение `2026-09-26T23:00`,
  то есть лага нет вовсе. За 2024-01-01 тоже 24 часа из 24,
  `weather_code` есть, `snow_depth` пуст.
- `models=era5_ensemble` (55 км) - лаг такой же, как у ERA5
  (последнее значение 2026-09-21T02:00). Может пригодиться как оценка
  неопределённости, для прототипа избыточен.
- `models=cerra` - за 2024-06-01..02 возвращает 0 непустых значений
  из 48. Совпадает с документацией: покрытие «1985 to June 2021».

Лимиты и лицензия бесплатного доступа (страница terms): CC BY 4.0,
«600 per minute», «5'000 per hour», «Less than 10'000 API calls per
day», бесплатный тариф определён как non-commercial (в него прямо
включены «public research» и «educational content»). Для хакатона это
подходит; в README решения нужна ссылка на Open-Meteo и на Copernicus
для ERA5.

### 3.3 Open-Meteo Previous Runs API - глубина архива

Документация прямо говорит: «Most models are archived from January
2024», с исключениями («GFS 2 m temperature - available from March
2021», «JMA GSM and MSM - available from 2018»). Проверка по дням
(`temperature_2m_previous_day1`, число непустых часов из 24):

| Дата | `ecmwf_ifs025` | `icon_seamless` | `gfs_seamless` |
|---|---|---|---|
| 2024-01-01 | 0 | 0 | 0 |
| 2024-01-15 | 0 | 0 | 0 |
| 2024-01-18 | - | 0 | 0 |
| 2024-01-22 | - | 24 | 24 |
| 2024-02-01 | 0 | 24 | 24 |
| 2024-02-02 | 0 | - | - |
| 2024-02-03 | 0 | - | - |
| 2024-02-04 | 21 | - | - |
| 2024-02-06 | 24 | - | - |
| 2024-03-01 и далее | 24 | 24 | 24 |

Итого: **до 2024 архив не дотягивается**. ICON и GFS начинаются между
18 и 22 января 2024, ECMWF IFS 0.25 - 4-5 февраля 2024 (4 февраля
неполные сутки, 21 час из 24). Первый месяц 2024 года прогнозными
признаками не закрыть.

Горизонты: `_previous_day1`, `_previous_day3`, `_previous_day5`,
`_previous_day7` на 2026-06-01 все по 24 часа, то есть доступны
лаги от 0 до 7 суток, а не только сутки.

Верхняя граница та же, что у historical-forecast: при
`end_date=2026-12-31` HTTP 400, «out of allowed range from 2016-01-01
to 2026-10-11».

### 3.4 Open-Meteo Forecast API: сколько прошлого он помнит

`https://api.open-meteo.com/v1/forecast?...&past_days=92&forecast_days=16`

HTTP 200, окно 2026-06-26T00:00 .. 2026-10-11T23:00 (2592 часа), но
непустых только 1892: пропуски идут подряд с начала окна и кончаются
на `2026-07-25T03:00`. То есть `past_days` реально наполнен примерно
на 62 суток назад, а не на заявленные 92. Для длинной истории нужен
historical-forecast, а не `past_days`.

### 3.5 rp5.ru (SYNOP, «Расписание Погоды»)

Метод получения (как в `collect_weather.py`): сначала GET `https://rp5.ru/`
для cookie, потом POST на `https://rp5.ru/responses/reFileSynop.php`
с `wmo_id`, `a_date1`, `a_date2` в формате `ДД.ММ.ГГГГ`,
`f_ed3=1&f_ed4=1&f_ed5=1&f_pe=1&f_pe1=2&lng_id=2&type=csv`,
заголовками `Referer: https://rp5.ru/` и
`X-Requested-With: XMLHttpRequest`. В ответе приходит HTML со ссылкой
на `*.csv.gz`, её надо забрать теми же cookie.

Проверка (станция 27612, ВДНХ):

- 01.01.2024 .. 05.01.2024: ссылка выдана
  (`https://a2.rp5.ru/download/files.synop/27/27612.01.01.2024.05.01.2024.1.0.0.ru.utf8.00000000.csv.gz`),
  40 строк за 5 суток = 8 сроков в сутки, все колонки на месте.
  Первая строка: `"01.01.2024 00:00";"-10.5";"741.7";"756.3";"1.5";"75";
  "Ветер, дующий с северо-запада";"3";...;"100%.";"Ливневый снег слабый
  в срок наблюдения"`.
- 01.02.2026 .. 07.02.2026: 56 строк за 7 суток, `T` 56, `WW` 40,
  `N` 56, `P` 56, `RRR` 28, `sss` 7 (значения 49.0, 49.0, 51.0 см).
  Для сравнения тот же период 2025 года: `WW` 23, `sss` 4
  («Менее 0.5»). То есть высота снега и явления в 2026 году
  доступны и даже полнее, чем в 2025.
- 20.09.2026 .. 26.09.2026: 977 строк за 7 суток, последняя -
  `26.09.2026 19:20`, то есть данные практически в реальном времени.
  **Но формат свежей недели другой:** `T`, `Po`, `U`, `DD`, `Ff`
  заполнены во всех 977 строках, а `P` 2, `N` 2, `WW` 19, `RRR` 2,
  `sss` 0. По станциям 27605 и 27618 за ту же неделю: ~974 строки,
  из них `N` ~55, `P` ~55, `RRR` 27, то есть кодированные сроки есть,
  но их приходится вылавливать среди плотных автоматических замеров.
  Вывод: для последних суток из rp5 надёжно берутся температура,
  влажность, давление на уровне станции и ветер, а облачность,
  осадки, явления и снег появляются позже, при консолидации в 8 сроков.

Атрибуция: rp5 просит указывать сайт «Расписание Погоды», rp5.ru.

Практическое: между запросами нужна пауза (в коллекторе 10 с);
запрос года целиком по одной станции работает.

### 3.6 Meteostat bulk hourly

URL: `https://data.meteostat.net/hourly/<ГОД>/<СТАНЦИЯ>.csv.gz`,
станции: `UUEE0`, `UUWW0`, `UUDD0`, `UUBW0`, `27612` и т. д.

Проверка:

- `2024/UUEE0.csv.gz` - HTTP 200, 78 478 байт, 8784 строки данных
  (полный високосный год), `last-modified: Sat, 04 Jul 2026 06:11:58 GMT`.
- `2025/UUEE0.csv.gz` - HTTP 200, 78 926 байт.
- `2026/UUEE0.csv.gz` - HTTP 200, 62 540 байт,
  `last-modified: Sat, 26 Sep 2026 12:40:29 GMT`, то есть файл
  обновлён в день проверки. Последнее наблюдение с `temp_source=metar`:
  2026-09-26 12 UTC (то есть лаг порядка часов).
- `2026/27612.csv.gz` - HTTP 200, `last-modified` 25.09.2026 19:18.
- Важная особенность: файл за текущий год содержит **прогнозный
  хвост**. Последние строки 2026 года - 2026-10-05 и 2026-10-06
  с `temp_source=metno_forecast`. Фильтр по `*_source` в коллекторе
  (`METEOSTAT_MODEL_SOURCES`) это уже отсекает, но при расширении
  на 2026 год фильтр обязателен, иначе прогноз попадёт в «факт».

Колонки файла: `year,month,day,hour,temp,temp_source,rhum,rhum_source,
prcp,prcp_source,wdir,wdir_source,wspd,wspd_source,wpgt,wpgt_source,
pres,pres_source,cldc,cldc_source,coco,coco_source`.
В нынешнем коллекторе не используются **`coco`** (код условий погоды,
то есть явления) и **`wpgt`** (порывы) - оба полезны для снегопадов
и ледяного дождя.

Лицензия: CC BY 4.0, «give credit to Meteostat and its meteorological
data providers», пример атрибуции в документации -
«Source: Meteostat, Deutscher Wetterdienst».

### 3.7 Iowa Environmental Mesonet, архив ASOS/METAR

Запрос (параметр `data` повторяется для каждой переменной):

```
https://mesonet.agron.iastate.edu/cgi-bin/request/asos.py
  ?station=UUEE&data=tmpf&data=relh&data=sknt&data=p01i&data=vsby
  &data=skyc1&data=wxcodes&data=feel
  &year1=2024&month1=1&day1=1&year2=2024&month2=1&day2=3
  &tz=Etc/UTC&format=onlycomma&latlon=no&missing=empty&trace=0.0001
  &direct=no&report_type=3&report_type=4
```

Проверка:

- 2024-01-01..03: HTTP 200, 5802 байта, 96 строк данных, шаг 30 минут.
  `UUEE,2024-01-01 00:00,10.40,78.35,11.66,0.00,6.21,BKN,-SN,-5.27` -
  то есть сразу есть `wxcodes` (`-SN`, слабый снег) и `feel`
  (ощущаемая температура, здесь -5.27 F).
- 2026-09-20..26: HTTP 200, 363 строки, последняя
  `UUEE,2026-09-26 16:00` - фактически реальное время.
- Точечные проверки середины периода: 2024-03 (49 строк),
  2024-12 (50), 2025-06 (62), 2025-11 (55) - то есть провала
  в 2025 году нет.
- **Лимит запросов заметный.** При серии запросов без паузы сервис
  отвечает HTTP 200 с пустым телом (0 строк, даже без заголовка).
  С паузой 6-8 секунд те же URL отдают данные. При выгрузке 2024-2026
  надо делать запрос на месяц-год с паузами, а не десятки быстрых.

Единицы американские: температура в F, ветер в узлах, осадки в дюймах,
видимость в милях. Есть параметры для SI, но проще пересчитать.

### 3.8 Прогноз вперёд: чем можно заменить «прошлогодние значения»

Команда сейчас подставляет для будущего периода прошлогоднюю погоду
(допущение 5 в `docs/THOUGHTS.md`). Проверенные бесплатные варианты:

**Open-Meteo Forecast API, 16 суток почасово.** HTTP 200,
2026-09-26T00:00 .. 2026-10-11T23:00, 384 часа, все переменные
заполнены полностью, включая `snowfall`, `snow_depth`, `weather_code`,
`apparent_temperature`.

**Open-Meteo Ensemble API, 16 суток, ансамбль.**
`https://ensemble-api.open-meteo.com/v1/ensemble?...&models=icon_seamless&forecast_days=16`
HTTP 200, 384 часа, 39 членов ансамбля по `temperature_2m`. Готовый
источник доверительного интервала для дашборда.

**Open-Meteo Seasonal API - до 7 месяцев.**
`https://seasonal-api.open-meteo.com/v1/seasonal?latitude=55.75&longitude=37.62&daily=temperature_2m_max,temperature_2m_min,precipitation_sum&timezone=Europe/Moscow`
HTTP 200, по умолчанию 183 суток: 2026-09-26 .. 2027-03-27,
50 членов ансамбля на каждую переменную.
С `forecast_days=210` горизонт растягивается до 2027-04-23.
Это буквально совпадает с горизонтом дашборда из `docs/THOUGHTS.md`
(«с ноября по апрель»), только шаг суточный.
Расхождение с документацией: она обещает «native 6-hour interval» и
51 член (модели ECMWF EC46 и SEAS5, EC46 обновляется ежедневно около
20:30 UTC, SEAS5 - 5 числа каждого месяца), но запрос с `six_hourly=...`
возвращает HTTP 200 вообще без блока данных, а членов приходит 50.
Верю пробе: практически доступен только суточный блок.

**ECMWF open data (open-data.ecmwf.int / data.ecmwf.int).**
Каталог живой: `https://data.ecmwf.int/forecasts/20260926/00z/`
содержит `ifs/`, `aifs-single/`, `aifs-ens/`, внутри
`ifs/0p25/oper/` - файлы вида
`20260926000000-102h-oper-fc.grib2` плюс `.index`. Лицензия CC BY 4.0,
0.25 градуса, шаг 3 ч до 144 ч и 6 ч до 360 ч. Минусы для нас:
хранится только «the most recent 12 forecast runs, corresponding to
approximately 2-3 days of forecasts», и нужен декодер GRIB2 (eccodes),
а коллектор у нас на стандартной библиотеке. Через Open-Meteo та же
модель доступна как JSON. Вердикт: возможно, но избыточно.

**Copernicus C3S сезонные прогнозы** (`seasonal-monthly-single-levels`
в CDS) - разрешение месячное и нужен аккаунт CDS. Для почасового
прототипа не даёт ничего сверх Open-Meteo Seasonal.

### 3.9 NASA POWER hourly

`https://power.larc.nasa.gov/api/temporal/hourly/point?parameters=T2M,PRECTOTCORR&community=RE&latitude=55.75&longitude=37.62&start=20240101&end=20240102&format=JSON&time-standard=UTC`

- HTTP 200, 48 часов, заголовок ответа:
  `{'title': 'NASA/POWER Source Native Resolution Hourly Data',
  'api': {'version': 'v2.10.2'}, 'sources': ['MERRA2'],
  'fill_value': -999.0}`.
- Лаг: запрос 2026-08-01..2026-09-26 вернул 1368 часов, из них
  валидны 1296, последний валидный час `2026092323`. То есть
  примерно 3 суток отставания - существенно лучше, чем у ERA5.
- Документация: «Hourly UTC and LST time standards data are available
  from 2001/01/01 to Near Real Time (NRT)». Численные лимиты запросов
  в документации не указаны, только упоминание кода 429.
- Осторожно с сеткой ~50 км: за 2024-01-02T23 UTC POWER даёт -33.67,
  тогда как Historical Forecast на тот же час показывает -21.7.
  Для «глобального индекса по Москве» POWER годится как
  дополнительный признак, но не как эталон.
- Снега и облачности по часам нет, давление только приземное.

https://www.ogimet.com/cgi-bin/getmetar?icao=UUEE&begin=202401010000&end=202401010600

  39912 40107 52023 77087 87500 333 87624==`. Это сырой SYNOP,

- `getsynop`, 27612, 2026-09-24..26: HTTP 200, 1816 байт, данные есть.

Вердикт: хороший резерв, если rp5 или Meteostat отвалятся. Явной

### 3.11 pogodaiklimat.ru

`http://www.pogodaiklimat.ru/weather.php?id=27612&bday=1&fday=31&amonth=1&ayear=2024&bot=2`

  по срокам UTC: `00 1.01 | 03 1.01 | 06 1.01 | ...`.
- Тот же URL на 26.09.2026: HTTP 200, 43 105 байт, данные до 15 UTC

## 4. Отклонённые источники и причина

- **Copernicus CDS (`reanalysis-era5-single-levels`)**. Описание
  процесса читается без ключа (HTTP 200), но `POST` на
  `.../execution` возвращает HTTP 401
  `{"type":"permission denied","detail":"authentication required"}`.
  Нужен аккаунт и принятие лицензии; аккаунт не создавался.
  Данные те же, что Open-Meteo отдаёт без регистрации, поэтому для
  хакатона смысла нет. Лаг ERA5T «about 5 days», финальная версия
  «2 to 3 months later».
- **NOAA ISD / Global Hourly**. `2024/27515599999.csv` (UUEE) -
  HTTP 200, 18 811 строк, последняя `2024-12-31T23:30:00`.
  `2025/27515599999.csv` - HTTP 200, 13 476 строк, последняя
  `2025-08-24T21:30:00`. `2026/27515599999.csv` - **HTTP 404**.
  В `isd-history.csv` у всех московских станций `END` стоит
  `20250824` (Шереметьево, Внуково, Домодедово), у ВДНХ `20250804`,
  у Остафьево `20240618`. По ВДНХ (`27612099999`) вообще 43 строки
  за 2024 год и 13 за 2025. Для 2026 года источник мёртв.
- **meteo.ru / ВНИИГМИ-МЦД**. Массив «Основные метеорологические
  параметры (срочные данные)» - именно то, что нужно (8 сроков в
  сутки с 1966 года, видимость, облачность, явления), но доступ
  только через АИСОРИ-М: страница `aisori-m.meteo.ru` предлагает
  «Переход на страницу авторизации», а на странице массива сказано:
  «доступ к массиву данных, выборка данных по интересующим
  пользователя станциям, их просмотр и копирование обеспечиваются
  специализированной технологией АИСОРИ». Прямых файлов нет ни у
  одного из проверенных массивов (`basic-parameters`,
  `temperature-precipitation`, `snow-cover`,
  `atmospheric-phenomena`) - все ведут на
  `aisori-m.meteo.ru/waisori/index.xhtml?idata=N`. Регистрация не
  проводилась. Обязательная библиографическая ссылка на массив
  указана на странице (Булыгина, Веселов, Разуваев, Александрова,
  свидетельство о регистрации базы данных № 2014620549).
- **Мосэкомониторинг и data.mos.gov.ru**. Из окружения проверки
  `data.mos.gov.ru` и `www.mos.ru` недостижимы (HTTP 000, имя не
  разрешается). `mosecom.mos.ru` отвечает HTTP 200, но в разделе
  «Метеоданные» опубликован единственный пункт - «Данные
  температурных профилемеров», а машиночитаемого API у разделов
  «Данные измерительных станций» и «Данные специальных станций»
  в разметке страниц не нашлось (только `wp-json` от WordPress).
  Отклонено как непроверяемое отсюда, см. открытые вопросы.
- **Open-Meteo `models=cerra`**. Покрытие «1985 to June 2021»;
  запрос 2024-06-01..02 вернул 0 непустых значений из 48.
- **Meteomanz**. `https://www.meteomanz.com/sy2?...&ind=27612&...`
  отвечает HTTP 200 и даже правильно подписывает страницу
  «MOSKVA VDNH - Weather data by days», но в HTML нет ни одной
  строки таблицы (`<tr>` - 0). Варианты `sy1`, `so=002`, `ord=REV`
  дали то же. Без браузерного рендеринга данные не достаются,
  а покрытие всё равно то же, что у Ogimet и rp5.
- **NOMADS (NOAA GFS)**. `https://nomads.ncep.noaa.gov/pub/data/nccf/com/gfs/prod/`
  (только по HTTP/1.1, по HTTP/2 сервер отдаёт битый заголовок
  `content-length`) содержит лишь `gfs.20260924`, `gfs.20260925`,
  `gfs.20260926`. Это оперативный каталог на 2-3 суток, не архив.
- **Visual Crossing**. Бесплатный план - 30 000 записей в месяц
  (порядка 1000 в сутки), почасовая история заявлена на 50 лет.
  Убийственно для нас условие лицензии: данные можно хранить
  «for shared internal use», но не «for shared external use», и
  «raw data can never be shared and distributed publicly for
  download». Критерий 2а требует дать рабочую ссылку на внешние
  данные, а выгрузку мы кладём в репозиторий - это прямой конфликт.
  Плюс 24 000 часов на одну точку выбрали бы месячную квоту.
- **Weatherbit**. Бесплатный план: 50 запросов в сутки, только
  текущая погода и прогноз на 7 суток, истории нет, «Non-Commercial
  Use».
- **Tomorrow.io**. Бесплатный план: «24 hours Historical Weather
  Data» и прогноз на 5 суток. Для двух лет истории бесполезен.
- **WorldWeatherOnline**. Требует регистрации; на странице цен
  глубина истории для бесплатного плана не документирована
  («generous daily API calls» без числа). Не проверялось дальше,
  так как аккаунт не создавался.
- **Яндекс Погода** и **Gismeteo API** - уже отклонены ранее,
  см. `data/README.md`, раздел «Что не вошло»: архив Яндекса
  платный (7 440 руб. за точку), Gismeteo API отдаёт только текущую
  погоду и прогноз по токену.

## 5. Открытые вопросы и что требует регистрации

Требуют аккаунта (и поэтому не проверялись дальше описания):

- **Copernicus CDS** - аккаунт ECMWF и принятие лицензии на каждый
  набор. Подтверждено кодом 401 на `execution`.
- **АИСОРИ-М (meteo.ru)** - логин ВНИИГМИ-МЦД. Это единственный
  найденный путь к официальным срочным данным Росгидромета с
  явлениями погоды и снегомерными съёмками. Если кто-то в команде
  готов зарегистрироваться, это плюс к критерию 2а: источник
  российский, официальный, с явлениями.
- **Visual Crossing, Weatherbit, Tomorrow.io, WorldWeatherOnline** -
  API-ключ. Все отклонены по существу, регистрация ничего не меняет.

Открытые вопросы:

1. **data.mos.gov.ru недостижим из окружения проверки** (HTTP 000).
   Портал открытых данных Москвы стоит перепроверить с российского
   адреса: там могут быть наборы Мосэкомониторинга с метеопараметрами
   по городским станциям. Это был бы самый «московский» источник
   из возможных, но подтвердить его отсюда нельзя.
2. **`snow_depth` у ERA5-Land расходится со станцией.** За
   2024-01-15 ERA5-Land даёт 0.58 м, тогда как Historical Forecast
   на 2024-01-01 показывает 0.19 м, а rp5 по ВДНХ в феврале 2026
   даёт 49-51 см. Прежде чем брать ERA5-Land как признак высоты
   снега, нужно сверить его с `sss` из rp5 за одну зиму. Ground
   truth по снегу - rp5 (`sss`) и Meteostat (`snwd`).
3. **Бесплатный тариф Open-Meteo определён как non-commercial.**
   Для хакатона («public research», «educational content») это
   подходит, но в описании ограничений решения стоит написать, что
   продуктивное использование потребует коммерческой подписки или
   self-hosted инстанса.
4. **Свежая неделя в rp5 приходит в другом формате** (плотные
   автоматические замеры без облачности, осадков, явлений и снега).
   Если коллектор будет дотягивать 2026 год до «сегодня», надо либо
   агрегировать плотные строки в 8 сроков, либо для последней недели
   брать явления из Meteostat `coco` / IEM `wxcodes`.
5. **Никакой бесплатный источник не даёт факт до 2026-12-31.**
   Максимум - «сегодня + 15 суток» (Open-Meteo, до 2026-10-11 на
   момент проверки) и суточный сезонный прогноз до 2027-04-23.
   Остаток периода всё равно придётся закрывать сезонным прогнозом
   или прошлогодними значениями, и это надо явно назвать в описании
   области применимости модели.
