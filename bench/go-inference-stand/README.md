# Пульт прогноза: CatBoost в Go, модель на каждый запрос

Go-сервис с интерактивным UI. Каждое действие в интерфейсе отправляет настоящий
HTTP-запрос, сервис строит признаки из календаря, прогоняет CatBoost cyclic и отдаёт
прогноз. Кэша нет. MLP убран: он давал +0.001 к WAPE-score ценой x6 по скорости.

## Запуск

```bash
cd bench/go-inference-stand
bash scripts/fetch_libs.sh                     # libcatboostmodel в lib/
python scripts/train_cyclic.py                 # model_cyclic.cbm + эталон ref_grid.csv (7 с)
go run ./cmd/check                             # Go против Python + скорость модели
go build -o bin/server ./cmd/server
./bin/server -auth jury:secret                 # http://localhost:8080, логин jury / secret
```

`model_cyclic.cbm` уже лежит в папке, так что для запуска сервера Python не обязателен.
На macOS, если сервер не находит библиотеку: `DYLD_LIBRARY_PATH=lib ./bin/server ...`.
Если `proxy.golang.org` недоступен: `export GOPROXY=direct`. Внешних Go-зависимостей нет.

## Что есть в UI

- **Управление слева**: маршрут (Shift/Cmd-клик - несколько, "Все" - обзор), период
  (день, неделя, месяц, ноябрь-декабрь), по часам или по дням, три корректирующих
  коэффициента. При изменении запрос уходит сразу.
- **Запрос**: URL, статус, сколько строк ушло в модель, время модели, сервера и полного
  пути до браузера. Полоса показывает, куда ушло время: разбор, признаки, CatBoost,
  свёртка и k, JSON, сеть. Цифры берутся из заголовка `Server-Timing`.
- **Прогноз**: один маршрут - столбцы по часам или линия по дням, несколько маршрутов -
  тепловая карта маршрут x время.
- **Как посчитана точка**: клик по столбцу или клетке шлёт `/api/v1/explain` и
  показывает весь путь: календарь, все 13 признаков в том виде, в каком они ушли в
  CatBoost (числа, строки категорий и их хэши), сырой выход модели, обрезку нуля,
  умножение на k и число в ответе.
- **Сценарии**: типичные запросы диспетчера, тяжёлый запрос на 7200 строк и запрос с
  ошибкой, чтобы увидеть ответ 400.
- **Нагрузка из браузера**: 1-12 параллельных потоков на 15 секунд. RPS, CPU и память
  сервис отдаёт сам через `/api/v1/stats`. Браузер держит не больше 6 соединений на сайт,
  так что это оценка снизу, честный замер делает `cmd/load`.
- **Ответ сервиса** и **журнал**: JSON ответа и последние 12 запросов; клик по строке
  журнала повторяет запрос.

## API

Всё под basic auth (`-auth user:pass`), кроме `/healthz`.

```
GET /api/v1/forecast?route=7,11&from=2025-11-10&to=2025-11-16&granularity=hour|day
                    &k_weather=0.9&k_event=1.1&k_season=1.0
GET /api/v1/explain?route=7&date=2025-11-10&hour=8&k_weather=0.9
GET /api/v1/forecast/export?...как forecast...   -> CSV (;)
GET /api/v1/model                                 -> модель, признаки, горизонт
GET /api/v1/stats                                 -> счётчики запросов, строк, CPU, память
GET /healthz
```

- `route` - список через запятую, пусто = все маршруты.
- `granularity=hour` - не больше 31 дня; неделя и месяц по дням (по QA-сессии).
- `k_*` перемножаются и умножают прогноз.
- Ответ forecast: `{"start": "2025-11-10T00:00", "step": "1h", "k", "series": [{"route",
  "total", "peak_index", "values": [...]}], "meta": {"rows", "model", "timings"}}`.
  Время точки i = `start + i * step`.
- Ошибки: `{"error": {"code", "message"}}` с понятным текстом (400/401/500).

## Производительность

Микс запросов диспетчера (`python scripts/gen_urls.py > urls.txt`): 60% маршрут за день
по часам (24 строки модели), 20% все маршруты за день (240), 15% маршрут за 30 дней по дням
(720), 5% все маршруты за 30 дней по часам (7200). Нагрузка `cmd/load` с соседнего ядра.

| Конфигурация | Нагрузка | Факт RPS | p50 | p95 | p99 | CPU | RSS |
|---|---|---:|---:|---:|---:|---:|---:|
| 1 vCPU | 1000 RPS | 1 000 | 1.8 мс | 32 мс | 57 мс | 73% | 30 МБ |
| 1 vCPU | максимум | 1 747 | 8.0 мс | 23 мс | 32 мс | 99% | 28 МБ |
| 2 vCPU * | максимум | 2 432 | 4.6 мс | 20 мс | 32 мс | 165% | 34 МБ |

\* генератор нагрузки делит эти ядра с сервисом.

```bash
./bin/load -urls urls.txt -rate 1000 -d 20s -pid $(pgrep -x server) -auth jury:secret
```

Модель: ~0.7 us на строку в батче, 625 деревьев глубины 8, 7 числовых и 6 категориальных
признаков. Вся сетка ноябрь-декабрь (14 640 строк) считается за 11 мс на одном ядре.

## Как сделана интеграция CatBoost

`.cbm` грузится официальной `libcatboostmodel` через свою cgo-обёртку `internal/cbfast`.

- **Хэши вместо строк.** catboost-cgo передаёт категории строками: `C.CString` на каждую
  ячейку, и библиотека хэширует их заново. Это 2.4 us на строку против 0.5 us у CatBoost
  в Python. `cbfast` один раз хэширует значения категорий функцией библиотеки
  (`GetStringCatFeatureHash`) и отдаёт батч в `CalcModelPredictionWithHashedCatFeatures`.
  Стало в 4.4 раза быстрее.
- **Строковая форма категорий.** Строки должны совпадать с тем, что CatBoost видел в pandas:
  `bool` - это `"0"/"1"`, не `"True"/"False"`. С `"True"` модель молча даёт другой прогноз
  (до 3177 посадок на ячейку).
- **Cyclic-признаки** (sin/cos часа, дня недели, дня месяца) считаются в Go по формулам
  `data_preparation.add_cyclic_features`.

Сверка: `scripts/train_cyclic.py` обучает модель тем же кодом, что `final_ensemble.py`, и её
прогноз совпадает с `artifacts/preds/catboost_cyclic_submit.parquet` бит в бит. Go-сервис
на всей сетке ноябрь-декабрь совпадает с Python тоже бит в бит, а в ответе API ни одна из
7440 проверенных ячеек декабря не отличается от `round(catboost.predict)`.

## Почему без MLP

WAPE-score на фолдах 3 и 4 (`artifacts/preds/oof_pooled.parquet`):

| Модель | Score |
|---|---:|
| 0.7 CatBoost cyclic + 0.3 MLP | 0.8892 |
| CatBoost cyclic | 0.8882 |
| MLP | 0.8833 |
| CatBoost base (лежит в `artifacts/catboost/model.cbm`) | 0.8811 |

MLP стоил ~5 us на строку против 0.7 у CatBoost, и сервис с ним держал 458 RPS на 1 vCPU.
Для CSV-сабмита смесь с MLP имеет смысл: там важна каждая тысячная.

## Ограничения

- Постобработка сабмита (калибровка route x weekday, `fill_route5`, новогодний блок) в
  сервис не перенесена, сервис отдаёт сырой прогноз CatBoost.
- Календарь только на 2025 год, поэтому горизонт - ноябрь-декабрь 2025.
- Маршрут 5 в истории пуст, модель даёт по нему почти нули.
- Контейнер не собран: Docker Hub из песочницы, где делался стенд, недоступен. Для образа
  нужен debian-slim с glibc; `libcatboostmodel` других зависимостей не требует.
