# Пульт прогноза: CNN через ONNX-раннер, модель на каждый запрос

Go-сервис с интерактивным UI и Python-раннер с CNN из `tram_forecast` (boarding-only,
горизонт 61 день). Каждое действие в интерфейсе отправляет настоящий HTTP-запрос: Go
разбирает его, одним запросом берёт у раннера прогноз маршрут x день x 24 часа, умножает
на коэффициенты и сворачивает до часов или дней. Кэша нет.

## Запуск

Из корня репозитория. Нужны чекпойнт `outputs/boarding_only_61days_v5_final/final.pt` и
`dataset/labels/labels_day_test.csv`, оба в git не лежат.

```bash
docker compose up -d --build                   # http://127.0.0.1:8090
STAND_AUTH=jury:secret docker compose up -d    # то же под basic auth
```

Другой чекпойнт: `docker compose build --build-arg CHECKPOINT=outputs/.../final.pt`.

Без Docker:

```bash
pip install -e '.[onnx]'
python -m tram_forecast export-onnx --checkpoint outputs/boarding_only_61days_v5_final/final.pt --output outputs/onnx
python -m tram_forecast serve --model outputs/onnx --labels dataset/labels/labels_day_test.csv
cd bench/go-inference-stand && go run ./cmd/server -runner http://localhost:8000
```

## Как считается прогноз

- `export-onnx` делит сеть на два графа: `encoder.onnx` (история 504 часа -> вектор 672)
  и `head.onnx` (вектор истории, маршрут, lead, sin/cos дня недели и дня месяца -> 24 часа).
  В Docker экспорт идёт на этапе сборки, в образ раннера torch не попадает.
- Раннер при старте строит историю 11-31 октября из `labels_day_test.csv` тем же
  `schema.label_grid`, что и подготовка данных для обучения, и один раз прогоняет энкодер
  по всем 9 маршрутам. Сверка: `scale` чекпойнта в точности равен среднему по labels
  январь-октябрь, то есть история совпадает с той, на которой училась модель.
- На запрос работает только голова: одна строка на маршрут x день.
- Маршрут 5 пуст в истории, сеть его не видела: раннер отдаёт 0, как `predict.py`.
- ONNX Runtime расходится с torch на реальном чекпойнте не больше чем на 4e-6
  относительной ошибки. `tests/test_onnx_runner.py` сверяет раннер с torch на случайных весах.

## Что есть в UI

- **Управление слева**: маршрут (Shift/Cmd-клик - несколько, "Все" - обзор), период
  (день, неделя, месяц, ноябрь-декабрь), по часам или по дням, три корректирующих
  коэффициента. При изменении запрос уходит сразу.
- **Запрос**: URL, статус, сколько строк ушло в модель, время модели, сервера и полного
  пути до браузера. Полоса показывает, куда ушло время: разбор, HTTP до раннера, CNN,
  свёртка и k, JSON, сеть. Цифры берутся из заголовка `Server-Timing`.
- **Прогноз**: один маршрут - столбцы по часам или линия по дням, несколько маршрутов -
  тепловая карта маршрут x время.
- **Как посчитана точка**: клик по столбцу или клетке шлёт `/api/v1/explain` и
  показывает весь путь: окно истории и среднее по этому часу в тот же день недели, вход
  головы сети, выход модели, умножение на k и число в ответе.
- **Сценарии**: типичные запросы диспетчера, тяжёлый запрос на 270 строк и запрос с
  ошибкой, чтобы увидеть ответ 400.
- **Нагрузка из браузера**: 1-12 параллельных потоков на 15 секунд. RPS, CPU и память
  сервис отдаёт сам через `/api/v1/stats`, но только по Go-процессу, раннер в них не входит.
- **Ответ сервиса** и **журнал**: JSON ответа и последние 12 запросов; клик по строке
  журнала повторяет запрос.

## API

Всё под basic auth (`-auth user:pass`), кроме `/healthz`.

```
GET /api/v1/forecast?route=7,11&from=2025-11-10&to=2025-11-16&granularity=hour|day
                    &k_weather=0.9&k_event=1.1&k_season=1.0
GET /api/v1/explain?route=7&date=2025-11-10&hour=8&k_weather=0.9
GET /api/v1/forecast/export?...как forecast...   -> CSV (;)
GET /api/v1/model                                 -> модель, раннер, горизонт
GET /api/v1/stats                                 -> счётчики запросов, строк, CPU, память
GET /healthz
```

- `route` - список через запятую, пусто = все маршруты.
- `granularity=hour` - не больше 31 дня; неделя и месяц по дням (по QA-сессии).
- `k_*` перемножаются и умножают прогноз.
- Ответ forecast: `{"start": "2025-11-10T00:00", "step": "1h", "k", "series": [{"route",
  "total", "peak_index", "values": [...]}], "meta": {"rows", "model", "timings"}}`.
  Время точки i = `start + i * step`.
- Ошибки: `{"error": {"code", "message"}}` с понятным текстом (400/401/502).

Раннер слушает только внутреннюю сеть compose:

```
GET /predict?route=7,5&from=2025-11-10&days=7    -> {"values": [[days*24]], "rows", "model_ms"}
GET /explain?route=7&date=2025-11-10              -> вход головы, история, 24 часа
GET /model                                        -> model.json, окно истории, движок
GET /healthz
```

## Производительность

Микс запросов диспетчера из `scripts/gen_urls.py`, `cmd/load` в той же сети compose,
Docker Desktop на Apple M-серии:

| Нагрузка | Факт RPS | p50 | p95 | p99 |
|---|---:|---:|---:|---:|
| 300 RPS | 300 | 2.1 мс | 6.4 мс | 10.9 мс |
| 1000 RPS | 1 000 | 1.6 мс | 9.4 мс | 78 мс |
| 8 потоков, максимум | 1 806 | 3.6 мс | 10.8 мс | 15.6 мс |

Потолок - один Python-процесс раннера с GIL. Весь горизонт по всем маршрутам (549 строк)
раннер считает за 9 мс.

## Ограничения

- Постобработка сабмита (калибровка route x weekday, `fill_route5`, новогодний блок) в
  сервис не перенесена, сервис отдаёт сырой прогноз CNN.
- Отсечка модели 1 ноября, поэтому горизонт - ноябрь-декабрь 2025.
